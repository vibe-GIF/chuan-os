## 1. 项目是什么

**川流 chuan-os**：本地多智能体操作系统。14 个角色 persona（律师/程序员/管家/幕僚长等）由 LangGraph supervisor 统一路由，配三层记忆（SqliteSaver 会话 + FTS5 长期检索 + Obsidian 黑板）、语音交互、Flutter 全息 HUD、微信通道。

技术栈：Python 3.13 + LangGraph 1.x / edge-tts / faster-whisper / openwakeword(onnx) / Silero VAD；Flutter 3.47（HUD）。

入口：
```
python -m chuan.main    # CLI 对话（/voice 切语音，/workers 看班底）
python -m chuan.voice   # 直接语音模式（免提）
python -m chuan.tui     # TUI 调试界面
```

### 3.3 免提唤醒（本阶段最重要的三项 bug 修复）

**架构**（`chuan/voice/main.py`）：常开麦克风流（0.16s 块）→ 空闲块喂 openwakeword → 命中 `WakeWord` 事件 → 自动应答 → 应答播完转录音（VAD 静音收尾）→ 识别 → 派发 → 播报 → 回监听。Enter 手动兜底并存；stdin 关闭不再杀死进程。

三个叠加 bug 的根因与修法（**交接必读，防复发**）：

1. **int16 尺度 bug**：openwakeword 按 int16 尺度（-32768..32767）训练，实时麦克风流是归一化 float32（-1..1），数值小 3 万倍 → 模型恒 0 分。修复：`wake_word.py detect()` 内部检测峰值 ≤1.0 则 ×32768。原仓库没踩坑是因为它直接用 int16 读麦克风；我们为了喂 whisper 用 float32，移植时丢了这步换算。
2. **滑动窗口污染**：openwakeword 的 `predict()` 是**有状态流式推理**（自持滚动缓冲），必须顺序、不重叠喂块。曾改成"重复喂最近 2s 窗口"反而污染内部状态恒低分——已回退为顺序流。**喂帧方式不可随意改**。
3. **旧进程旧代码**：改完代码用户说"还是不行"，其实是旧 `python -m chuan.voice` 进程还挂着跑旧逻辑。调试前先清进程。

模型部署：`hey_jarvis.onnx` + `melspectrogram.onnx`/`embedding_model.onnx`（~/.openwakeword/models/ + openwakeword 包内 resources/models/），`inference_framework="onnx"`（Python 3.13 无 tflite-runtime）。

端到端离线验证方法（合成音频 16 相位流式喂 + 中文负样本）：16/16 命中、零误触。

### 3.4 贾维斯式唤醒自动应答（移植自 assistant-x-openclaw）

- **话术**：`config/config.yaml` → `wakeword.wake_lines`（6 条管家话术，随机挑）："在的，先生。请讲。" / "随时待命，先生。" 等。
- **专属音色**：`wakeword.wake_voice: zh-CN-YunjianNeural`（青年男声）+ 语速 +15% + **金属滤镜链**。
- **金属链**（[chuan/voice/tts.py](../../chuan/voice/tts.py) `apply_metallic()`）：ffmpeg aecho/chorus/bass/treble/highpass/lowpass（参数抄自原仓库 assistants.json），实测频谱变化 80%；ffmpeg 缺失自动回退原声。`speak(text, voice=, rate=, metallic=)` 签名扩展。
- **时序**：应答播报期间 `listener.arm()`——用户开口立即打断应答转录音（回声门限自适应，金属应答声不会误触发）。

```powershell
d:\Dev\Active\chuan-os\hud_overlay\build\windows\x64\runner\Release\assistant_overlay.exe

# 2. 启动语音模式（前台跑便于看提示）
```

体验：说 **"hey jarvis"**（完整两个词，嘿·杰维斯）→ 提示音 + HUD 唤醒 + 金属男声应答（"在的，先生。请讲。"）→ 直接说指令（VAD 自动收尾）→ 语音回复 → 回到监听。全程不碰键盘。说「再见」退出。

```powershell

Start-Process python -ArgumentList '-m','chuan.voice' -WorkingDirectory 'D:\Dev\Active\chuan-os' `
  -RedirectStandardOutput 'D:\Dev\Active\chuan-os\.voice.log' `
  -RedirectStandardError 'D:\Dev\Active\chuan-os\.voice.err.log'
Get-Content .voice.log -Tail 20 -Wait   # 看日志
```

```powershell

```

## 7. 踩坑速查（再遇到按此排查）

| 症状 | 根因 | 处置 |
|---|---|---|
| 唤醒词说了没反应 | ① 旧进程跑旧代码 ② 没说完整 "hey jarvis" ③ 尺度 bug 复发 | 先杀全部 `chuan.voice` 进程重启；对着 `.voice.log` 看 |
| 改了唤醒喂帧方式后全 0 分 | openwakeword 有状态流被污染 | 只能顺序不重叠喂块；改喂法前回看 §3.3 |
| HUD 没反应/对话不上屏 | HUD 进程没起或端口占用 | 起 exe；`Test-NetConnection 127.0.0.1 -Port 17889` |
| flutter clean 后构建失败 | 插件符号链接丢失 | 跑 `scripts\fix_plugin_symlinks.ps1`（package.bat 已自动） |
| PowerShell 脚本中文乱码/语法错 | UTF-8 无 BOM 被 GBK 解析 | 存为 UTF-8 with BOM |
| 后台起语音秒退 | stdin 关闭触发 EOF 退出 | 已修（保持常驻）；确认跑的是新代码 |
| 下载 LFS 大文件失败 | git lfs 缓存缺失 | 走 ModelScope `/resolve/master/` 直连下载 |
